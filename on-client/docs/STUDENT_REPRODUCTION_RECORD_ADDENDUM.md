# 22단계 재현 기록 보완 — 대상 식별·기능별 관찰·보존 계획

> **상태: 정적 원문 확인 · 새 환경 재현 미실행.** 이 보완 기록은 Git 원격·커밋 및 실제 PC 환경·화면 결과를 모두 도구로 확인한 것은 아닙니다. 저장소 브랜치·HEAD·작업 트리 상태는 사용자가 전달한 Git Bash 출력에 근거합니다. 코드 읽기는 새 환경 실행이나 성공 인증을 뜻하지 않습니다. 미확인 값을 꾸며 쓰지 않았습니다.

## 1. 제출 대상과 식별 가능한 원문

| 항목 | 확인 결과 | 근거·한계 |
|---|---|---|

| 패키지·버전 | `alekov-client-starter` · `0.2.11` | `on-client/package.json`. `docs/FINAL_PRODUCT_GUIDE.md`의 `starter 0.2.9`와 차이가 있습니다. 어느 쪽도 임의 수정하지 않았습니다. |
| Git 저장소 최상위 | `DAAT-defense/` | 사용자가 전달한 `git rev-parse --show-toplevel` 출력의 경로 끝부분입니다. 로컬 절대경로는 재현성에 필요하지 않아 기록하지 않습니다. |
| 저장소 URL | 미확인 | 전달된 출력에 원격 URL이 없습니다. 인증정보가 포함될 수 있으므로 URL을 요청하거나 기록하지 않습니다. |

| 실제 PC 환경 | OS·PowerShell·Node·브라우저 버전 미확인 | 로컬 명령·브라우저 제어 기능이 없어 실제 환경을 조사하지 않았습니다. |

**재현 대상 식별:** `e7b638be20c463aad7235bf3e3a1aff071fbdfb6`은 사용자가 전달한 `git rev-parse --verify HEAD` 결과이며, 파일 SHA-256과 구별되는 Git 소스 커밋입니다. 별도 폴더에서 재현할 때는 그 폴더의 `git rev-parse HEAD`가 이 값과 일치하는지 확인합니다. 아래 Git 조회 명령은 사용자가 원본 프로젝트에서 실행한 결과를 제공했습니다. 이 작업에서는 실행하지 않았습니다.

```bash
git rev-parse --show-toplevel
git status --short
git branch --show-current
git rev-parse --verify HEAD
```

기록된 커밋 이후 문서 변경을 포함한 새 커밋을 만들면, 그 새 커밋은 위 대상과 다릅니다. 새 커밋의 실행 재현을 주장하려면 새 커밋 기준으로 다시 재현하고 관찰을 별도로 기록하세요. 기존 변경을 보존하고 확인 없이 `reset`, `clean`, 삭제 또는 덮어쓰기를 하지 마세요.

## 2. 기능별 코드 관찰·미확인 사유

다음은 `student/extension.mjs`를 읽고 확인한 **코드 표시 분기**입니다. 실행 결과는 아닙니다.

| 단계 | 정적으로 확인한 학생 함수 동작 | 실행 결과 / 구체적 미확인 사유 |
|---|---|---|
| 13 | `renderIdentity`: 사용자·기기·세션 식별 정보와 상태, loading·ok·error 및 demo·disconnected·unknown 모드를 구분합니다. | 미확인: 앱을 실행하거나 실제 계정 자료를 불러오지 않았습니다. |
| 14 | `renderDecision`: 요청 전·중·결과·오류를 나누고 판정 코드·한국어 뜻·이유·시각을 표시합니다. 요청 실패와 접근 거부를 별도로 안내합니다. | 미확인: 업무 앱 요청을 보내지 않았고, 실제 판정 결과를 받을 수 있는 실행 환경을 확인하지 않았습니다. |
| 15 | `renderEvents`: 입력 배열을 복사해 시간순 정렬하고 종류·앱·접속 상태 필터, 기록 상세·근거·규칙·세 상태 표시, 빈 결과와 실패 구분을 합니다. | 미확인: 실제 로그가 제공되지 않았고 브라우저 필터·상세·갱신 동작을 실행하지 않았습니다. |
| 16 | `renderStatus`: 기기·세션 loading·빈 목록·오류, 알림 및 정해진 진단 항목을 표시합니다. 도움정보는 사용자가 버튼을 눌렀을 때 복사하는 구조입니다. | 미확인: 화면·클립보드·다시 불러오기·네트워크 요청을 확인하지 않았습니다. |
| 17 | `renderAiConnection`: idle·loading·ok·error 및 시험/verified 연결을 구분하고 모델 수·시각·오류별 후속 안내를 표시하며 연결 점검과 설명 실행을 구별합니다. | 미확인: 운영 계정 권한과 API 점검을 실행하지 않았습니다. 기존 disconnected 진단은 해당 시각의 값뿐입니다. |
| 18 | `renderExplanation`: 이벤트 근거 ID를 현재 기록과 대조하고 요약·근거·규칙·unknown 상태·미실행 제안을 표시하는 분기가 있습니다. 실패·근거 불일치에는 성공 표식을 붙이지 않습니다. | 미확인: 외부 AI 설명을 요청하거나 서로 다른 이벤트의 근거 연결을 시험하지 않았습니다. 비용이 발생할 수 있는 요청은 반복하지 않았습니다. |
| 19 | `renderAction`: 준비·전달·접수·거절·실패·불명·만료·오류를 구분합니다. `observation.effectApplied === true`일 때만 효과 확인으로 표시하고 학생 함수가 직접 요청을 전송하지 않습니다. | 미확인: 모의 입력·시험 집행·실제 집행을 실행하지 않았습니다. 운영 집행 연결은 완료된 것으로 기록하지 않습니다. |
| 20 | `renderVulnerabilities`: 전체 및 패키지별 미조회·부분 실패·확인 불가·취약점 결과, 전달된 설치 버전·출처·시각·ID를 표시하는 분기가 있습니다. | 미확인: lockfile 버전 대조, OSV 조회 및 결과 화면을 실행하지 않았습니다. 패키지를 변경하거나 취약점을 인위적으로 만들지 않았습니다. |

**수행한 것:** 프로젝트 원문 열람, 학생 코드·문서 계약의 정적 대조. Git 상태·브랜치·HEAD 정보는 사용자가 Git Bash에서 실행한 결과를 전달했으며, 도구가 직접 실행한 결과는 아닙니다.  
**수행하지 않은 것:** 별도 폴더 복제, OS·런타임 조회, 앱·브라우저, 모의 데이터, 네트워크·AI·OSV 요청, 보안 조치, 백업·복원.  
**미확인의 구체적 이유:** 파일 읽기·쓰기 도구만 제공되어 로컬 명령·브라우저·새 폴더 재현을 수행할 수 없습니다. 그러므로 실제 관찰 성공을 주장하지 않습니다.

## 3. 새 폴더 재현 시 기록할 사항

이 절의 절차는 아직 실행되지 않았습니다.

1. 원본 폴더와 미커밋·미추적 파일을 보존하고, 사용자가 제공한 원본 Git 상태·브랜치·`HEAD`를 재현 기준으로 기록합니다. 현재 기록된 대상 커밋은 `e7b638be20c463aad7235bf3e3a1aff071fbdfb6`입니다.
2. 원본 바깥 새 폴더에서 동일 저장소·커밋을 체크아웃하고 새 폴더의 `git rev-parse HEAD`를 비교합니다. 저장소 URL은 이 기록에서 확인되지 않았으므로 본인이 확인한 저장소를 사용하되, 인증정보를 기록·공유하지 않습니다. 원본 인증·계정·SDP·Native Host 설정 및 개인 데이터를 무작정 복사하지 않습니다.
3. 새 `on-client`에서 OS, `node --version`, PowerShell 버전을 기록하고 `docs/STUDENT_RUNBOOK.md` 및 `docs/STUDENT_LAUNCH_GUIDE.md`를 따릅니다. 서버 시작, 브라우저 화면, 종료, 재실행의 실제 관찰을 단계별로 기록합니다. demo와 실제 운영 연결을 구별합니다.
4. 결과 기록을 수정해 새 커밋을 만들면 그 새 커밋을 최종 재현 대상으로 삼습니다. 그 새 커밋에 대한 재현 실행을 하지 않았다면 재현 완료로 표시하지 말고, 이전 커밋의 관찰 결과를 다른 커밋 결과와 합치지 않습니다.

## 4. 데이터별 보존·백업·복원 계획

소스 원문에서 아래 선택 기능의 구현은 확인했지만, 이 PC에서 설정·사용 중인지와 실제 데이터 존재 여부는 조사하지 않았습니다. 아래 계획은 백업·복원 수행 기록이 아닙니다. Git clone만으로 비소스 데이터가 복구된다고 보지 않습니다.

| 데이터 종류 / 사용 조건 | 보존 대상 및 안전한 백업 방법 | 복원·재승인 책임과 제한 |
|---|---|---|
| 학생 파일·미커밋 작업 | 원본 폴더를 유지하고 별도 접근 제한 위치에 사본을 둡니다. `git status --short`, diff와 미추적 학생 파일을 확인하되 원본 자체도 보존합니다. 자격·비밀 파일은 Git이나 일반 사본에 포함하지 않습니다. | 학생이 사본과 원문을 비교해 필요한 학생 파일만 복원합니다. 무차별 덮어쓰기, `reset --hard`, `clean`, 삭제로 보존하지 않습니다. 새 커밋은 다시 재현해야 합니다. |
| SQLite 조치 원장(조치 저장소를 설정·사용한 경우에만) | 소스의 조치 저장소는 기존 SQLite DB에 `alekov_action_intents`, `alekov_action_state`, `alekov_action_audit` 테이블을 사용할 수 있습니다. DB 소유자/운영 담당자가 실제 DB 경로·사용 여부를 확인하고, 안전한 정지 후 일관성 있는 SQLite 백업 API/도구로 복사해 프로젝트 밖 제한된 위치에 둡니다. 열린 DB/WAL을 일반 파일 복사만으로 일관되게 백업했다고 가정하지 않습니다. | DB 소유자·운영 담당자가 현재 원장과 백업 시점을 비교해 복원합니다. 과거 원장 복원으로 조치를 재집행하지 않습니다. 과거 상태로 현재 결과를 덮어쓰거나 반복 요청하지 말고, 영수증·효과가 불명확하면 담당자가 원천 시스템에서 대조합니다. 미사용 시 원장이 없을 수 있습니다. |
| 별도 Native Host 원장(호스트 기능을 구성·사용한 경우에만) | `tools/native-host-registry.ps1`은 Windows Registry 키가 아니라 전용 `registryRoot`의 `.alekov-native-registry.json` 및 `.native-history-*.bak` 파일을 다룹니다. 운영 담당자가 실제 위치와 사용 여부를 확인하고, 호스트를 정지한 뒤 전용 디렉터리를 프로젝트 외부 접근 제한 위치에 보존합니다. 프로젝트·컨텍스트·credential/token digest 등 민감할 수 있는 메타데이터 때문에 공유·Git에 넣지 않습니다. 이를 Windows Registry 내보내기로 대체하지 않습니다. | Native Host 운영 담당자가 같은 사용자·프로젝트 맥락, ACL·무결성·현재 상태를 검토해 복원합니다. 오래된 JSON이나 `.bak`를 현재 상태에 무검토로 덮지 않습니다. 실제 디렉터리·파일 및 별도 Windows Registry 등록 존재는 미확인입니다. |
| Native Host 설정 파일(별도 준비한 경우에만) | 준비 스크립트가 쓰는 프로젝트 밖 설정 위치를 운영 담당자가 확인하고, 비밀이 아닌 필요한 설정만 제한된 프로젝트 외부 백업에 둡니다. 설정 파일 존재 여부는 미확인입니다. | 운영 담당자가 경로·ACL·프로젝트 결속을 검토한 뒤 공식 준비 절차로 재구성합니다. 설정만으로 계정 권한·자격은 복구되지 않습니다. |
