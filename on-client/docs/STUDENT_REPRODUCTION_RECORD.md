# 다아트 새 환경 재현 기록 및 버전 기록

> **현재 상태: 초안 · 새 환경 재현은 미실행 · 검증 중**  
> 이 문서는 22단계 기록의 빈칸을 실제 확인 전에 채워 넣지 않도록 만든 학생 기록입니다. 빈칸·「미확인」은 통과나 실행 완료를 뜻하지 않습니다. 실행 결과를 확인한 학생만 관찰한 값과 근거를 갱신하세요.

### 버전 원문 차이

현재 `README.md`와 `package.json`은 시작 틀 버전 `0.2.11`을 가리킵니다. `docs/FINAL_PRODUCT_GUIDE.md` 제목에는 `starter 0.2.9`라고 적혀 있어 버전 표기가 서로 다릅니다. 이 기록은 실제 `package.json` 값 `0.2.11`을 패키지 버전으로만 적으며, 제공 기준 문서의 표기를 임의로 고치거나 두 값을 같은 버전이라고 간주하지 않습니다. 이 불일치는 최종 원문 검토 때 확인할 사항입니다.

## 2. 기존 작업과 데이터 보존 계획

1. 원래 프로젝트 폴더를 보존하고 재현을 위해 이동·초기화·삭제·덮어쓰지 않습니다. 새 재현 폴더는 원래 폴더 바깥에 만듭니다.
2. 복제 전에 원래 프로젝트에서 `git status --short`, 현재 브랜치와 `HEAD`를 직접 확인합니다. 커밋되지 않은 학생 작업이 있으면 이를 버리지 말고 보존한 다음, 제출 대상으로 선택한 커밋을 확정합니다. `git reset --hard`, `git clean`, 원본 폴더 삭제 또는 무작정 파일 복사를 사용하지 않습니다.
3. 새 환경에는 제출할 커밋의 추적 파일만 가져옵니다. 기존 폴더의 인증·계정·SDP·Native Host 설정, 토큰, 개인키, 임시 파일을 새 폴더나 저장소에 복사하지 않습니다. 담당자가 새 환경용 개인 설정을 별도로 안내한 경우에만 저장소 바깥의 안전한 위치에서 그 지침을 따릅니다.
4. 앱이 사용하는 별도 로컬 자료나 개인 설정의 종류·백업 형식·복원 절차는 이 문서 작성 시 실제 환경에서 조사하지 않았습니다. 따라서 이를 자동 백업하거나 복원한다고 주장하지 않습니다. 별도 자료가 발견되면 내용·민감도·보존 위치를 먼저 확인하고 담당자 승인 절차를 따릅니다.
5. 복제·실행 뒤 원본의 Git 상태와 파일이 바뀌지 않았는지 다시 확인하고, 새 재현 폴더와 원본을 혼동하지 않도록 경로를 기록합니다. 복구가 필요하면 원본 폴더를 보존한 채 해당 폴더로 돌아갑니다. 기록되지 않은 로컬 자료의 복구는 미확인으로 남깁니다.

## 3. 같은 커밋을 새 폴더에서 확인하는 절차

아래는 실행 전 준비 절차입니다. 이 문서 작성 중 Git 명령, 복제, 설치, 서버 실행, 브라우저 확인 또는 재실행을 수행하지 않았습니다. 실제 저장소 URL·브랜치·해시·PC 경로를 확인하기 전에는 자리표시자를 실제 값처럼 사용하지 마세요.

### 3.1 원본 폴더에서 제출 커밋 확인

Git Bash에서 **원래 저장소의 최상위 폴더**로 이동한 뒤 다음 읽기 명령을 사용합니다.

```bash
git rev-parse --show-toplevel
git status --short
git branch --show-current
git rev-parse HEAD
git remote -v
```

기록할 것은 실제 제출 저장소 URL, 브랜치와 40자리 `HEAD`입니다. `git remote -v` 결과에 자격 정보가 들어 있으면 출력물을 공유하지 말고 URL의 비밀 부분을 제거한 뒤 처리합니다. 작업 트리에 미커밋 변경이 있으면 해당 내용과 기존 작업을 먼저 보존하고, 어떤 버전을 제출할지 정한 후 진행합니다. 이 기록의 작성자는 Git 상태를 읽을 수 있는 실행 도구를 갖고 있지 않아 위 값을 대신 확인하지 않았습니다.

### 3.2 별도 폴더에 복제하고 커밋을 고정

저장소가 원격에 있다면 원래 폴더와 겹치지 않는 새 위치에 복제하고, 제출할 커밋을 detached 상태로 체크아웃합니다.

```bash
git clone --no-checkout "<실제 저장소 URL>" "<원본 밖의 새 재현 폴더>"
cd "<새 재현 폴더>"
git checkout --detach <제출할 40자리 커밋>
git rev-parse HEAD
git status --short
```

원격에 올리지 않은 로컬 커밋을 확인해야 한다면 원래 폴더를 출처로 삼아 별도 복제할 수 있습니다. 새 폴더를 원본 안에 만들지 않습니다.

```bash
git clone --no-hardlinks --no-checkout "<원래 저장소 최상위 폴더 경로>" "<원본 밖의 새 재현 폴더>"
cd "<새 재현 폴더>"
git checkout --detach <제출할 40자리 커밋>
git rev-parse HEAD
git status --short
```

`git rev-parse HEAD`가 제출 해시와 정확히 같은지 확인하고, 새 폴더의 추적 변경이 없는지 확인합니다. 일치하지 않거나 복제가 실패하면 재현으로 기록하지 않습니다. 기존 저장소의 비공개 여부와 인증 방식은 학생이 실제 ALEPH 과제 화면의 지침으로 확인합니다. 자격 정보나 비공개 저장소 내용을 대화에 보내지 않습니다.

### 3.3 런타임 확인·실행·종료·재실행

`docs/STUDENT_RUNBOOK.md` 3장과 `docs/STUDENT_LAUNCH_GUIDE.md`에 따라 새 복제본의 `on-client` 폴더에서 진행합니다. Windows PowerShell에서 다음을 확인하고 실행합니다.

```powershell
Get-Location
node --version
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

PowerShell의 현재 위치가 새 복제본의 `on-client`인지 확인합니다. 수업 기준 Node.js는 `24.19.0`이며 실행 도구는 Node.js 22~24를 허용합니다. 서버 준비 메시지는 로컬 서버 응답만 뜻합니다. 브라우저에서 `http://127.0.0.1:5189/`을 직접 열어 13~21단계 확인표를 관찰합니다. 포트가 바뀌었다면 실제 출력된 포트를 사용합니다. 종료는 실행한 PowerShell에서 `Ctrl+C`입니다. 같은 새 폴더에서 다시 실행하고, 재실행 뒤 관찰 결과도 따로 적습니다.

일반 실행과 `-Demo` 실행은 구분합니다. 예제 데이터는 실제 계정·회사 시스템 연결이 아니며, demo 결과를 실제 연결 성공이나 단계 성취로 기록하지 않습니다. 새 환경에서 추가 패키지 설치가 필요하다고 추측하지 않습니다. 현재 `package.json`에는 외부 `dependencies`가 선언되어 있지 않습니다.

### 기능 범위와 결과의 의미

- 본인 최근 기록과 저장된 XDR 경보는 제공 서버가 전달한 범위에 한정됩니다. 전체 직원 로그나 새 위협 탐지라고 넓혀 쓰지 않습니다.
- `allow`는 정책상 접근 허용이지 앱 접속 성공 보증이 아닙니다. `challenge`가 추가 인증을 대신하지 않습니다. `unknown`은 확인 불가입니다.
- AI 연결 점검은 사건 설명 실행과 다릅니다. 실제 계정 권한이나 AI 응답을 관찰하지 않았다면 연결·설명은 미확인입니다.
- AI 설명은 참고 정보이며 조치를 실행하지 않습니다. `pending`/ACK는 효과 확인이 아닙니다. 효과는 서버 관측이 실제로 확인된 경우에만 적습니다. 현재 지원 조치가 비어 있거나 실제 집행 연결이 준비되지 않은 상태를 완료로 쓰지 않습니다.
- OSV의 조회 결과 없음은 조회 범위에서 알려진 취약점이 없다는 뜻이지 앱 전체의 안전 보증이 아닙니다. 실패·미조회·확인 불가를 `none_found`와 합치지 않습니다.

## 5. 최종 재현 결과 갱신란

실제 새 폴더 실행 후에만 아래를 채웁니다.

- 재현 대상 저장소/브랜치/40자리 커밋: **미확인**
- 새 폴더에서 `HEAD`가 같은지 확인: **미확인**
- 운영체제 / PowerShell / Node.js / 브라우저 버전: **미확인**
- 실행·브라우저 접속·종료·재실행 시각과 관찰 결과: **미확인**
- 실제 연결 여부와 demo 여부: **미확인**
- 기존 폴더·기록 보존 여부를 확인한 근거: **미확인**
