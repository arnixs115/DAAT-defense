# 다아트 새 환경 재현 기록 및 버전 기록

> **현재 상태: 정적 원문 확인 · 새 환경 재현 미실행 · 검증 중**  
> 이 문서는 정적 코드 관찰과 새 환경 실행 관찰을 분리합니다. Git 저장소 정보는 사용자가 전달한 Git Bash 출력으로 기록했습니다. PC 환경·화면 관찰·백업 상태는 확인하지 않았습니다. 코드 읽기와 AI 원문 검토는 새 환경 실행 또는 성공 인증이 아닙니다.

| 릴리스 상태 | **검증 중; v1.0 아님** | 기록된 소스 커밋을 별도 폴더에서 실행한 결과가 없습니다. |

**재현 대상 식별:** 위 40자리 값은 사용자가 전달한 `git rev-parse --verify HEAD` 결과이며, 파일 SHA-256과 구별되는 Git 소스 커밋입니다. 별도 폴더에서 재현할 때는 그 폴더의 `git rev-parse HEAD`가 이 값과 일치하는지 확인합니다. 아래 Git 조회 명령은 사용자가 원본 프로젝트에서 실행한 결과를 제공했습니다. 이번 도구 작업에서는 명령을 직접 실행하거나 새 폴더를 만들지 않았습니다.

```bash
git rev-parse --show-toplevel
git status --short
git branch --show-current
git rev-parse HEAD
```

이후 변경을 커밋해 재현 기록의 내용을 포함시키는 경우, 그 새 커밋은 위에 적힌 현재 대상 커밋과 다릅니다. 별도 폴더 실행을 새 커밋 기준으로 주장하려면 새 커밋을 대상으로 다시 재현하고 해당 관찰을 따로 기록하세요. 기존 작업을 보존하고 `reset`, `clean`, 삭제, 덮어쓰기를 하지 마세요. 저장소 주소에 인증정보를 포함하지 마세요.

## 2. 새 폴더 재현 절차와 환경 기록

사용자가 전달한 Git 조회 결과로 원본 프로젝트의 브랜치 `master`, 대상 `HEAD` `e7b638be20c463aad7235bf3e3a1aff071fbdfb6`, 조회 당시 비어 있던 `git status --short`를 기록했습니다. 이번 도구 작업에서는 별도 폴더 복제, 서버 실행, 브라우저 확인, 종료·재실행은 하지 않았습니다. 다음은 학생이 직접 진행할 절차입니다.

1. 원본 폴더와 기존 작업을 보존하고 기록된 소스 커밋이 재현 대상인지 확인합니다. 재현 대상은 `e7b638be20c463aad7235bf3e3a1aff071fbdfb6`입니다.
2. 원본 외부의 새 폴더에 동일 저장소의 해당 커밋을 체크아웃하고 새 폴더의 `git rev-parse HEAD`가 대상 값과 같은지 비교합니다. 저장소 URL은 기록되지 않았으므로 본인이 확인한 저장소를 사용하되, 인증정보를 기록·공유하지 않습니다. 인증·SDP·Native Host 설정이나 사용자 데이터를 무작정 복사하지 않습니다.
3. 새 폴더의 `on-client`에서 OS·PowerShell·실제 Node 버전을 기록하고 `docs/STUDENT_RUNBOOK.md`, `docs/STUDENT_LAUNCH_GUIDE.md`를 따릅니다. 시작 명령은 `powershell -NoProfile -ExecutionPolicy Bypass -File .\\tools\\start-alekov.ps1`입니다. 브라우저에서 `http://127.0.0.1:5189/`과 실제 화면을 확인합니다.
4. 서버를 종료한 뒤 같은 새 폴더에서 재실행해 관찰을 따로 기록합니다. demo 결과와 실제 연결 결과를 구분합니다.
5. 이 기록을 수정하여 새 커밋을 만들면 그 새 커밋을 최종 대상으로 삼습니다. 그 새 커밋에 대한 재현 실행을 하지 않았다면 재현 완료로 표시하지 말고, 서로 다른 커밋의 결과를 합치지 않습니다.

**실제로 수행한 확인:** 프로젝트 파일 원문 열람 및 코드·문서 계약의 정적 대조. Git 상태·브랜치·HEAD 정보는 사용자가 Git Bash에서 실행한 결과를 전달했으며, 도구가 직접 실행한 결과는 아닙니다.  
**수행하지 않은 확인:** 별도 폴더 복제, OS·런타임 조사, Node/PowerShell, 앱·브라우저, 모의 데이터, 네트워크·AI·OSV 요청, 보안 조치, 백업·복원.  
**미확인 사유:** 제공 도구는 프로젝트 파일을 읽고 쓸 수 있지만 명령 실행·PC·브라우저 제어는 할 수 없습니다. 따라서 확인하지 않은 실제 결과를 성공 또는 실패로 만들지 않았습니다.

## 3. 데이터 보존·백업·복원 계획

Git 커밋은 소스만 보존합니다. 원장·호스트 상태·자격이 자동 복구되는 것은 아닙니다. 아래 선택적 코드 경로는 원문에서 확인했으나 현재 PC에서 설정·사용 중인지 또는 실제 데이터가 존재하는지는 조사하지 않았습니다. 이 계획에 따른 백업·복원은 수행하지 않았습니다.

| 데이터 종류 / 사용 조건 | 보존 대상·안전한 백업 방법 | 복원·재승인 담당 및 제한 |
|---|---|---|
| 학생 파일·미커밋/미추적 작업 | 원본 폴더를 유지하고 접근 제한된 위치에 사본을 둡니다. `git status --short`, diff, 미추적 학생 파일을 확인합니다. 인증·비밀 파일은 Git이나 일반 사본에 넣지 않습니다. | 학생이 사본과 원본을 대조해 필요한 학생 파일만 복원합니다. `reset --hard`, `clean`, 삭제 또는 새 복제본에 대한 무차별 덮어쓰기를 하지 않습니다. 새 커밋을 만들면 다시 재현합니다. |
| SQLite 조치 원장(조치 저장소를 설정·사용한 경우만) | 구현은 SQLite의 `alekov_action_intents`, `alekov_action_state`, `alekov_action_audit` 테이블을 사용합니다. DB 소유자/운영 담당자가 경로와 사용 여부를 확인하고, 쓰기 작업을 안전하게 멈춘 뒤 SQLite 백업 API/도구로 일관된 백업을 만들어 프로젝트 외부의 접근 제한 위치에 둡니다. 열린 DB/WAL을 단순 파일 복사해 일관성이 보장된다고 간주하지 않습니다. | DB 소유자·운영 담당자가 현 상태와 백업 시점을 확인해 복원합니다. 과거 원장을 복원해 조치를 재집행하지 않습니다. 과거 상태로 현재 결과를 덮거나 반복 요청하지 말고, 불명확한 영수증·효과는 담당자가 원천 시스템에서 대조합니다. 사용하지 않았다면 원장은 없을 수 있습니다. |
| 별도 Native Host 원장(호스트 기능을 구성·사용한 경우만) | `tools/native-host-registry.ps1`은 Windows Registry가 아니라 별도 `registryRoot` 디렉터리 안의 `.alekov-native-registry.json`과 `.native-history-*.bak` 파일을 관리합니다. 운영 담당자가 실제 경로·사용 여부를 확인한 뒤 호스트 작업을 멈추고 전용 디렉터리 전체를 프로젝트 밖 접근 제한 위치에 보존합니다. 파일에는 프로젝트·컨텍스트 정보와 credential/token digest 등 민감할 수 있는 메타데이터가 있으므로 저장소·공유 위치에 넣지 않습니다.
